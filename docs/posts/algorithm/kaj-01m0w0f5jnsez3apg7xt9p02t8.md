# 70. 爬楼梯 + LCR 126. 斐波那契数

![正文图片](/images/kajspace/0b69323c72b644ab.png)![正文图片](/images/kajspace/8bc75a8cd5260acb.png)

**70. 爬楼梯**和**LCR 126. 斐波那契数**的核心解题思路相同，本质上都是利用递推关系求解斐波那契数列。两道题都可以采用**递归 + 记忆化搜索**的方式：通过 `memory` 数组记录已经计算过的子问题结果，当递归过程中再次遇到相同的子问题时，直接读取缓存结果，避免重复计算，从而将原本指数级的重复递归优化为 **O(n)** 的时间复杂度。

### 两道题的共同点 {#kaj-h-d49c8940-b78a-4e3d-9215-9a42ea62e099}

- **本质相同**：都是利用 `f(n) = f(n-1) + f(n-2)` 的递推关系。
- **状态定义相似**：

  

  - 爬楼梯：`f(n)` 表示爬到第 `n` 阶的方法数。
  - 斐波那契数：`f(n)` 表示第 `n` 个斐波那契数。
- **核心优化相同**：使用 `memory` 数组保存已经计算过的结果，避免重复计算。
- **解题思想**：**递归拆解问题 → 发现重复子问题 → 使用记忆化缓存 → 降低时间复杂度**。

### 一句话总结 {#kaj-h-dd7d84af-ef32-4752-ae57-53ceac416a99}

> **这两道题本质上都是斐波那契型动态规划问题，核心是利用** `f(n)=f(n-1)+f(n-2)` **的递推关系，并通过记忆化避免重复计算，将递归的指数级复杂度优化到 O(n)。**

不过需要注意：**“都是计算斐波那契数”略显绝对**。更准确地说是\*\*“具有斐波那契型的递推关系”\*\*，因为“爬楼梯”计算的并不是标准定义下的斐波那契数，而是与斐波那契数列存在对应关系。
