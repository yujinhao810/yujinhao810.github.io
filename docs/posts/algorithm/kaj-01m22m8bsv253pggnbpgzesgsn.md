# 283. 移动零

自己的思路：`i` 不断向后寻找非 0 元素，`zeroid` 始终记录前面第一个 0 的位置；一旦找到非 0，就把它和这个 0 交换，从而把非 0 向前移动。

![正文图片](/images/kajspace/fe39ca3a5723ba6b.png)

看完题解，这个算法还是有点绕了，遍历的次数比较多。  
题解的思路是:

### 核心思路 {#kaj-h-de45c0d5-5db1-42ed-ba5d-f6b5e05a7131}

维护两个指针：

```text
i       // 快指针：遍历整个数组，寻找非零元素
start0  // 慢指针：指向下一个非零元素应该放置的位置
```

循环过程中始终保持：

```text
[ 已处理的非零元素 | 已处理的零元素 | 未遍历 ]
                       ↑             ↑
                     start0          i
```

---

### 遇到非零元素 {#kaj-h-02fe685b-d06f-42ad-861a-3b88adb3040c}

```js
if (nums[i] !== 0) {
    [nums[i], nums[start0]] = [nums[start0], nums[i]];
    start0++;
}
```

意思是：

> `i` 找到一个非零元素，就把它放到 `start0` 所指的位置，然后 `start0` 向后移动。

例如：

```text
[1, 0, 3, 0, 5]
    ↑     ↑
  start0  i
```

`i` 找到 `3`：

```text
交换
↓
[1, 3, 0, 0, 5]
    ↑
  start0++
```

继续找 `5`：

```text
[1, 3, 0, 0, 5]
        ↑     ↑
      start0  i
```

交换：

```text
[1, 3, 5, 0, 0]
```

---

### 为什么这样最终零会全部到后面？ {#kaj-h-2f4a4f0b-1b44-4607-8d4c-5cdb0216aae8}

因为：

- `i` 从左到右遍历所有元素；
- 每遇到一个非零元素，就把它放到 `start0`；
- `start0` 只在找到非零元素后向右移动；
- 因此 `start0` 左边最终全部都是非零元素；
- 剩下的位置自然全部是 `0`。

---

### 面试时可以直接这样总结 {#kaj-h-6473a070-7dfd-44b4-9944-f037b7613399}

> **使用双指针，**`i` **负责遍历数组寻找非零元素，**`start0` **指向下一个非零元素应该放置的位置。每当** `i` **遇到非零元素，就将其与** `start0` **位置交换，并让** `start0` **后移。遍历结束后，所有非零元素都会被稳定地移动到数组前面，零元素自然集中到末尾。整个过程原地完成，时间复杂度 O(n)，空间复杂度 O(1)。**

其中最值得记住的是：

`i`**：找非零 →** `start0`**：放非零。**
