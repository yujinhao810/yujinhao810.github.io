# 322. 零钱兑换

![正文图片](/images/kajspace/87e28a02b212bac2.png)

### 322. 零钱兑换 {#kaj-h-dc69ba80-a0e4-437a-b067-1d6aea98241d}

**做题复盘：**

这道题当时没有第一时间想到动态规划，而是习惯性地从全局考虑：如何直接计算凑出 `amount` 所需要的最少硬币数量。但这种方式很难直接确定最优解，因为一个金额可以有很多种硬币组合，需要不断比较不同方案。

这道题真正的突破点是：**不要直接考虑怎么凑出最终的** `amount`**，而是从小金额开始，逐步计算每个金额的最优解。**

因此定义一个 `dp` 数组：

> `dp[i]` 表示凑出金额 `i` 所需要的最少硬币数量。

先设置：

```text
dp[0] = 0
```

表示凑出 0 元不需要硬币，其余状态初始化为 `Infinity`，表示暂时还没有找到凑出该金额的方法。

然后从 `1` 开始，依次计算：

```text
dp[1]
dp[2]
dp[3]
...
dp[amount]
```

计算某个金额时，尝试使用每一种硬币。

假设当前要计算 `dp[curamount]`，选择一枚面值为 `coin` 的硬币作为最后一枚硬币，那么在使用这枚硬币之前，需要先凑出：

```text
curamount - coin
```

所以：

```text
dp[curamount - coin] + 1
```

就表示使用当前硬币的一种方案。

因为最后一枚硬币可能有多种选择，所以取所有方案中的最小值：

```text
dp[curamount] = Math.min(
    dp[curamount],
    dp[curamount - coin] + 1
);
```

最终得到 `dp[amount]`，如果仍然是 `Infinity`，说明无法凑出目标金额，返回 `-1`。

---

### 算法总结 {#kaj-h-4598c0af-6d3f-4bb4-970f-3f13b4dc2e1e}

这道题的核心是**动态规划 + 状态转移**。

思考过程可以总结为：

```text
不要直接考虑：
“怎么凑出 amount？”

而是考虑：
“怎么凑出 1？”
“怎么凑出 2？”
“怎么凑出 3？”
...
“怎么凑出 amount？”
```

每一个小金额的最优解都会成为后面计算的基础。

状态定义：

```text
dp[i] = 凑出金额 i 所需要的最少硬币数量
```

状态转移：

```text
dp[i] = min(dp[i - coin] + 1)
```

其中 `coin` 遍历所有硬币。

### 这道题对动态规划的理解 {#kaj-h-1afd5874-472f-416d-b058-2d8365e7c611}

这次没有想到动态规划，主要是之前习惯从**最终问题出发**，试图直接计算 `amount` 的答案。

而动态规划的思路是把一个大的问题拆成很多个**规模更小、结构相同的子问题**：

```text
凑出 amount
   ↓
凑出 amount - coin
   ↓
凑出更小的金额
   ↓
最终到达 dp[0]
```

并且这些子问题的答案可以保存下来，后面直接使用，而不需要重复计算。

因此这道题可以帮助建立一个很重要的 DP 思维：

> **当一个问题要求“求最优解”，并且大问题可以由更小规模的同类问题推导出来时，可以尝试定义** `dp[i]`**，从最小规模开始逐步计算最终答案。**
