# HTTP和HTTPS的区别，HTTPS 建立连接的完整过程

## 一、HTTP 和 HTTPS 的区别 {#kaj-h-3e0549d6-f0eb-4d46-90d1-476fc6fb9e12}

一句话先记：

> **HTTPS = HTTP + TLS 加密。**

HTTP 本身负责的是“**传输什么数据**”，HTTPS 在 HTTP 的基础上增加了 TLS，解决了数据传输过程中的**窃听、篡改和身份冒充**问题。

| 对比 | HTTP | HTTPS |
| --- | --- | --- |
| 全称 | HyperText Transfer Protocol | HTTP Secure |
| 加密 | ❌ 明文传输 | ✅ TLS 加密 |
| 安全性 | 较低 | 较高 |
| 默认端口 | 80 | 443 |
| 证书 | 不需要 | 通常需要服务器证书 |
| 数据是否容易被窃听 | 是 | TLS 下难以直接窃听 |
| 数据是否容易被篡改 | 是 | TLS 可检测篡改 |
| 身份认证 | 没有 TLS 证书提供的服务器身份认证 | 有 |
| 性能 | 通常更简单 | TLS 会增加握手开销，但现代 HTTPS 性能影响通常很小 |

### HTTPS 主要解决三个问题 {#kaj-h-f057484d-e870-4048-b647-9b4a4445d7fb}

可以记成：

> **加密 + 完整性 + 身份认证**

### 1. 加密 {#kaj-h-210eabdd-9a4d-4afa-820f-ad27b62716da}

HTTP：

```text
客户端  -------- "username=admin&password=123" --------> 服务器
                    ↑
                  黑客可以窃听
```

HTTPS：

```text
客户端  -------- 加密数据 --------> 服务器
                    ↑
                 即使被截获
                 也难以直接读懂
```

---

### 2. 防止篡改 {#kaj-h-36f17d5e-c845-4454-87e9-151ae9f5d5f1}

比如你请求：

```text
商品价格 = 100 元
```

中间人可能尝试修改成：

```text
商品价格 = 1 元
```

TLS 会对通信数据进行完整性保护，使通信双方能够发现数据是否被篡改。

---

### 3. 身份认证 {#kaj-h-3002bba5-c217-4cdc-a6e9-96a70f79dcea}

HTTPS 还可以通过**数字证书**验证：

> “你访问的这个服务器，确实是这个域名对应的服务器。”

例如：

```text
https://www.example.com
```

浏览器会验证服务器提供的证书是否可信、域名是否匹配、是否过期等。

---

## 二、HTTPS 到底是怎么建立连接的？ {#kaj-h-93b05160-b80e-4a91-830c-0e09b23a20eb}

这是面试最重要的部分。

你可以先记住整个流程：

```text
浏览器
  ↓
DNS
  ↓
TCP 三次握手
  ↓
TLS 握手
  ↓
验证服务器证书
  ↓
协商加密参数
  ↓
生成会话密钥
  ↓
HTTP 加密通信
```

注意：

> **HTTPS 不是直接替代 TCP，而是在 TCP 连接建立之后，再进行 TLS 握手。**

---

## 三、HTTPS 完整连接过程 {#kaj-h-d2612eee-3dec-4ebb-96b0-9a4ec749176e}

以浏览器访问：

```text
https://www.example.com
```

为例。

---

## 第一步：DNS 解析 {#kaj-h-560f018b-fea4-4bd7-85c4-2348695d6039}

浏览器首先需要知道：

```text
www.example.com
```

对应哪个 IP。

例如：

```text
www.example.com
        ↓
   DNS 查询
        ↓
192.0.2.10
```

---

## 第二步：TCP 三次握手 {#kaj-h-884ec7f2-0471-48bd-b66f-a6e4e9f315ce}

拿到 IP 后，浏览器与服务器建立 TCP 连接。

```text
客户端                         服务器

   SYN --------------------->

       <--------------------- SYN + ACK

   ACK --------------------->
```

三次握手完成：

```js
客户端 ===================== 服务器
          TCP连接建立
```

到这里为止，其实和 HTTP 的 TCP 连接没有本质区别。

---

## 四、第三步：TLS 握手 {#kaj-h-582e28d1-05e5-4dd3-a81f-88db5454ebe5}

这是 HTTPS 和 HTTP 最大的区别。

TLS 的核心目标是：

> **让客户端和服务器安全地协商出后续通信使用的加密密钥。**

现代 HTTPS 通常使用 **TLS 1.3**，面试时最好以 TLS 1.3 为主，同时知道 TLS 1.2 的经典流程。

---

## 五、TLS 1.3 握手怎么理解？ {#kaj-h-8ea8885c-39d5-457b-9c84-fb67b404ef27}

可以把它理解成：

```text
客户端                         服务器

ClientHello ------------------>

                 <------------ ServerHello
                 <------------ Certificate
                 <------------ CertificateVerify
                 <------------ Finished

Finished --------------------->

        ↓
开始加密 HTTP 通信
```

重点不是死记每个报文，而是理解：

> **双方先协商算法和密钥材料，然后服务器证明自己的身份，最后双方得到相同的会话密钥。**

---

## 六、ClientHello {#kaj-h-f851dbc5-525e-45d0-818b-d101d4d855dd}

客户端首先告诉服务器：

> “我支持这些 TLS 版本、加密算法，并且我提供了一份密钥交换参数。”

例如：

```text
ClientHello

支持 TLS 1.3
支持的密码套件
随机数
密钥交换参数
```

可以简单理解为：

```text
客户端：
我支持 TLS 1.3
我支持这些加密方式
这是我的密钥交换信息
```

---

## 七、ServerHello {#kaj-h-1b08d032-23c8-4e5b-a13c-238231ff2cca}

服务器收到之后，从客户端支持的方案中选择一个。

```text
ServerHello
```

例如：

```text
TLS版本：TLS 1.3
密码套件：某种 AES/ChaCha20 + 哈希组合
密钥交换：ECDHE
```

然后服务器继续发送自己的：

```text
Certificate
```

也就是**数字证书**。

---

## 八、数字证书是什么？ {#kaj-h-4b41545f-aac7-4c4d-a9b2-eed4da04f6b7}

这是 HTTPS 面试非常容易被问到的地方。

数字证书可以简单理解成：

> **服务器的“身份证”。**

证书里面包含类似：

```text
域名：www.example.com
服务器公钥
证书有效期
证书颁发机构 CA
数字签名
...
```

比如：

```text
www.example.com
       ↓
数字证书
       ↓
服务器公钥
```

---

## 九、浏览器为什么相信这个证书？ {#kaj-h-94865728-56e9-4238-854d-cf5a02ed1540}

因为证书通常是由：

> **CA（Certificate Authority，证书颁发机构）**

签发的。

例如：

```text
        CA
        ↓
验证 example.com
        ↓
签发证书
        ↓
服务器
```

浏览器操作系统中预置了一批可信 CA 的根证书。

因此浏览器可以验证：

```text
服务器证书
      ↓
是否由可信 CA 签发？
      ↓
域名是否匹配？
      ↓
是否过期？
      ↓
证书链是否有效？
```

如果验证失败，浏览器就可能提示：

```text
您的连接不是私密连接
```

---

## 十、服务器为什么还要证明“自己拥有私钥”？ {#kaj-h-98ccb9db-5a67-4163-b1d9-733c48c1eebe}

这里非常重要。

证书里面有：

```text
服务器公钥
```

但服务器真正掌握的是：

```text
服务器私钥
```

服务器需要证明：

> “这个证书对应的私钥确实在我手里。”

TLS 1.3 中服务器会通过：

```text
CertificateVerify
```

使用自己的私钥进行签名。

客户端利用证书中的公钥验证这个签名。

于是：

```text
服务器私钥
    ↓
生成签名
    ↓
客户端
    ↓
使用服务器公钥验证
```

验证成功：

> 服务器确实拥有对应私钥。

---

## 十一、那真正传输数据的时候，用什么加密？ {#kaj-h-06ee9c59-3734-4d63-8573-db8bd31a9571}

这里是很多面试最容易混淆的地方。

**不是每次 HTTP 请求都使用非对称加密。**

HTTPS 通常是：

```text
非对称密码学
      ↓
身份认证 + 密钥交换
      ↓
得到会话密钥
      ↓
对称加密
      ↓
大量 HTTP 数据传输
```

为什么？

因为：

> **对称加密速度快，非常适合大量数据传输。**

而非对称加密计算成本比较高。

---

## 十二、会话密钥怎么来的？ {#kaj-h-6d0b611e-1099-4a09-8cb9-bfd70a4ffe3f}

现代 TLS 通常使用：

> **ECDHE 等密钥交换机制**

双方各自产生自己的临时密钥材料：

```text
客户端                         服务器

客户端密钥材料                 服务器密钥材料
       \                         /
        \                       /
         ↓                     ↓
             密钥交换
                 ↓
          相同的会话密钥
```

最终：

```text
客户端：Session Key = ABC123

服务器：Session Key = ABC123
```

但是这个会话密钥不是直接在网络上传输的。

这就是非常关键的一点：

> **双方通过密钥交换计算出相同的密钥，而不是把真正的会话密钥明文发给对方。**

---

## 十三、开始 HTTP 通信 {#kaj-h-3e3de214-4bfd-43a2-883f-73ff7fc27045}

TLS 握手完成之后：

```js
客户端 ======================== 服务器
           TLS安全通道
```

然后 HTTP 请求就可以通过这个安全通道传输了。

例如：

```text
GET /user/info HTTP/1.1
Host: example.com
```

但在网络上传输时，实际上是：

```text
HTTP数据
   ↓
TLS加密
   ↓
密文
   ↓
网络
```

服务器收到后：

```text
密文
 ↓
TLS解密
 ↓
HTTP请求
 ↓
业务处理
```

---

## 十四、把整个过程串起来 {#kaj-h-09131b7e-50c3-4ac7-90c3-f44512204954}

你面试的时候可以直接这样回答：

> **HTTPS 本质上是在 HTTP 和 TCP 之间增加了一层 TLS，通过 TLS 对 HTTP 数据进行加密，同时提供身份认证和数据完整性保护。**
> 
> 
> 
> 浏览器访问 HTTPS 网站时，首先进行 DNS 解析获得服务器 IP，然后通过 TCP 三次握手建立 TCP 连接。TCP 连接建立之后进行 TLS 握手，客户端发送 ClientHello，告诉服务器自己支持的 TLS 版本、密码套件以及密钥交换参数；服务器返回 ServerHello，并发送自己的数字证书。浏览器会验证证书的有效性、域名以及证书链，并通过 CertificateVerify 等机制确认服务器拥有对应私钥。
> 
> 
> 
> 随后客户端和服务器通过 ECDHE 等密钥交换机制协商出相同的会话密钥。TLS 握手完成后，后续 HTTP 请求和响应都会使用这个会话密钥进行对称加密，同时保证数据的完整性。
> 
> 
> 
> 所以 HTTPS 的核心就是：**通过证书解决身份认证，通过密钥交换建立会话密钥，再通过对称加密保护后续 HTTP 通信。**

---

## 十五、你一定要记住这个图 {#kaj-h-50b3a4bb-c39b-45f9-b621-40a96e42083e}

```text
                浏览器访问 HTTPS
                       │
                       ↓
                  DNS 解析
                       │
                       ↓
                 TCP 三次握手
                       │
                       ↓
                  TLS 握手
                       │
          ┌────────────┴────────────┐
          ↓                         ↓
    ClientHello                ServerHello
                                    │
                                    ↓
                              数字证书
                                    │
                                    ↓
                              浏览器验证证书
                                    │
                                    ↓
                           密钥交换（ECDHE）
                                    │
                                    ↓
                         双方得到会话密钥
                                    │
                                    ↓
                            TLS 握手完成
                                    │
                                    ↓
                         HTTP 请求/响应
                                    │
                                    ↓
                         对称加密传输数据
```

### 最核心的一句话 {#kaj-h-23691160-2b5a-4b28-9284-d0a7770fa1a0}

面试官如果追问：

**“HTTPS 为什么安全？”**

你就回答：

> **因为 HTTPS 使用 TLS：通过数字证书进行身份认证，通过密钥交换建立会话密钥，再使用对称加密保护后续 HTTP 数据，同时提供数据完整性校验。**

再往下追问时，你就按：

**证书 → CA → 公钥/私钥 → ECDHE → 会话密钥 → 对称加密**

这条线继续展开即可。
