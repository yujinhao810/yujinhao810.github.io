# JavaScript 执行上下文、作用域链与调用栈的执行顺序

在学习 JavaScript 执行机制时，经常会遇到三个概念：**执行上下文（Execution Context）、作用域链（Scope Chain）和调用栈（Call Stack）**。

它们之间存在密切联系，但负责的事情不同：

- 执行上下文：记录代码执行所需的环境信息。
- 作用域链：决定变量如何查找。
- 调用栈：管理函数调用的执行顺序。

理解这三个概念的关键，是弄清楚它们在函数调用过程中分别什么时候创建、什么时候生效，以及什么时候销毁。

## 一、什么是执行上下文？

执行上下文是 JavaScript 引擎执行代码时使用的环境，包含当前代码执行所需的信息，例如变量绑定、词法环境和 `this` 等。

常见的执行上下文有：

1. 全局执行上下文：执行全局代码时使用。
2. 函数执行上下文：每次调用函数时创建。
3. Eval 执行上下文：执行 `eval()` 中的代码时使用。

例如：

```javascript
let a = 1;

function foo() {
  let b = 2;
  console.log(a, b);
}

foo();
```

执行这段代码时，会涉及全局执行上下文和 `foo` 的函数执行上下文。

全局代码执行时，全局执行上下文处于执行状态；调用 `foo()` 后，会创建对应的函数执行上下文，执行函数内部的代码。

需要注意，函数定义和函数调用是两件不同的事情。函数定义时会建立函数对象及其词法环境关系，而函数执行上下文是在函数实际调用时创建的。

## 二、什么是作用域链？

作用域链决定了 JavaScript 代码在访问变量时，应该按照什么顺序查找变量。

JavaScript 采用词法作用域，也叫静态作用域。函数的外层作用域主要由函数定义的位置决定，而不是由函数调用的位置决定。

例如：

```javascript
let a = 1;

function foo() {
  let b = 2;

  function bar() {
    let c = 3;
    console.log(a, b, c);
  }

  bar();
}

foo();
```

当 `bar()` 执行 `console.log(a, b, c)` 时：

- 查找 `c`：在 `bar` 自己的词法环境中找到。
- 查找 `b`：在 `bar` 的外层词法环境，即 `foo` 的环境中找到。
- 查找 `a`：继续向外，在全局词法环境中找到。

变量查找路径可以表示为：

`bar 的词法环境 → foo 的词法环境 → 全局词法环境`

这条逐级查找的路径就是我们通常所说的作用域链。

需要注意，现代 JavaScript 规范使用词法环境（Lexical Environment）等机制描述变量查找。作用域链是帮助理解这一机制的常用概念，并不意味着引擎一定会创建一个独立的数组来保存所有作用域。

## 三、函数定义时，作用域链就创建了吗？

这里需要区分两个时间点：函数定义时和函数调用时。

### 1. 函数定义时

例如：

```javascript
let a = 1;

function foo() {
  console.log(a);
}
```

当 JavaScript 创建函数对象 `foo` 时，会建立它与定义位置对应的外层词法环境之间的关联。

因此，`foo` 以后执行时，能够按照定义位置的词法环境查找变量 `a`。

### 2. 函数调用时

当执行：

```javascript
foo();
```

JavaScript 会为这次调用创建函数执行上下文，并建立当前执行所需的词法环境关系。

执行 `console.log(a)` 时，就会从当前环境开始，沿着外层词法环境查找变量。

因此，更准确的理解是：

**函数定义时，外层词法环境关系已经确定；函数调用时，创建本次执行上下文，并根据这些关系进行变量查找。**

并不是执行到某一行代码时，JavaScript 才临时把所有外层作用域拼接起来。

## 四、什么是调用栈？

调用栈是 JavaScript 引擎管理函数调用的一种栈结构，遵循后进先出（LIFO）的原则。

函数调用时，对应的执行上下文会进入执行上下文栈；函数执行结束后，对应的上下文退出调用栈，程序恢复到之前的执行位置。

例如：

```javascript
function a() {
  b();
}

function b() {
  console.log('hello');
}

a();
```

执行过程如下：

1. 全局代码开始执行，全局执行上下文处于调用栈中。
2. 调用 `a()`，`a` 的函数执行上下文进入调用栈。
3. `a()` 调用 `b()`，`b` 的函数执行上下文进入调用栈。
4. `b()` 执行完毕，`b` 的执行上下文退出调用栈。
5. `a()` 继续执行，执行完毕后，`a` 的执行上下文退出调用栈。
6. 全局代码继续执行。

可以把调用栈简化表示为：

```text
调用 a()：

全局执行上下文
全局执行上下文 → a 的执行上下文

a 调用 b()：

全局执行上下文
全局执行上下文 → a 的执行上下文 → b 的执行上下文

b 执行完毕：

全局执行上下文
全局执行上下文 → a 的执行上下文

a 执行完毕：

全局执行上下文
```

这里需要注意，调用栈管理的是执行上下文的执行顺序，而不是作用域链。作用域链负责变量查找，两者不能混为一谈。

## 五、执行上下文、作用域链和调用栈的整体顺序

将三个概念结合起来，可以使用下面的例子理解：

```javascript
let a = 1;

function foo() {
  let b = 2;

  function bar() {
    let c = 3;
    console.log(a, b, c);
  }

  bar();
}

foo();
```

### 第一步：执行全局代码

JavaScript 开始执行全局代码，使用全局执行上下文。

全局环境中建立了变量 `a` 和函数 `foo` 等相关绑定。

此时，函数 `foo` 的定义位置已经决定了它的外层词法环境关系。

### 第二步：调用 foo()

执行 `foo()` 时，创建 `foo` 的函数执行上下文，并进入对应的执行流程。

`foo` 的词法环境中包含局部变量 `b` 等绑定，同时保留其外层环境关系。

### 第三步：调用 bar()

执行 `bar()` 时，创建 `bar` 的函数执行上下文，并进入调用栈。

`bar` 的外层词法环境关系指向定义它的位置，也就是 `foo` 对应的词法环境。

### 第四步：查找变量

执行：

```javascript
console.log(a, b, c);
```

变量查找分别沿着以下路径进行：

- `c`：当前 `bar` 的词法环境。
- `b`：外层 `foo` 的词法环境。
- `a`：继续向外，全局词法环境。

这里，作用域链决定变量在哪里查找，而调用栈决定当前执行的是哪个函数。

### 第五步：函数执行结束

`bar()` 执行完毕后，其执行上下文退出调用栈，程序回到 `foo()` 的执行位置。

随后 `foo()` 执行完毕，其执行上下文也退出调用栈。

需要注意，执行上下文退出调用栈，并不意味着对应的所有对象一定立即被垃圾回收。如果闭包等结构仍然引用相关词法环境中的数据，这些数据仍可能继续存活。

## 六、一个容易混淆的问题：先创建作用域链，还是先入栈？

从 JavaScript 规范层面看，函数调用涉及创建执行上下文、建立词法环境以及切换当前执行上下文等过程。不能简单地把它们理解为所有引擎都严格执行的几条独立指令。

为了便于学习，可以记忆为：

1. 函数定义时，建立函数与外层词法环境的关联。
2. 函数调用时，创建本次调用的执行上下文。
3. 建立当前执行所需的词法环境及其外层环境关系。
4. 当前执行上下文进入执行流程，成为当前执行上下文。
5. 执行函数代码，变量查找沿词法环境关系进行。
6. 函数执行结束，恢复之前的执行上下文。

其中，调用栈的入栈和出栈是对执行上下文管理机制的常用描述。具体内部实现可能经过优化，不应将这种教学模型理解为引擎必须逐条执行的底层步骤。

## 七、总结

执行上下文、作用域链和调用栈可以分别理解为三个不同的机制：

| 概念 | 主要作用 | 关键时间点 |
| --- | --- | --- |
| 执行上下文 | 提供代码执行所需的环境信息 | 全局代码执行及函数调用时 |
| 作用域链 | 决定变量的查找路径 | 函数定义时建立外层环境关联，执行时进行变量查找 |
| 调用栈 | 管理执行上下文的调用顺序 | 函数调用时进入，执行结束后退出 |

最后记住：

**函数定义决定词法作用域关系，函数调用创建本次执行上下文，调用栈管理执行顺序，作用域链负责变量查找。**

理解这四句话，就能把 JavaScript 的执行上下文、作用域链和调用栈联系起来。
