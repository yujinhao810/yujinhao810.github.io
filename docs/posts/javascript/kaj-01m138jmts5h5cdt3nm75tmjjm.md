# CSS-浮动

关于浮，为什么可以从以下主线来分析：

**为什么产生浮动-&gt;浮动带来什么问题-&gt;如何清除-&gt;BFC为什么能解决-&gt;margin重叠和BFC的关系**

## 一、什么是浮动？ {#kaj-h-22e2fc03-c162-474e-8a7b-f1f02b2cbf2b}

`float` 最初主要用于实现**文字环绕图片**，后来也被大量用于页面布局。

```text
.left {
    float: left;
}
```

设置浮动后，元素会**脱离普通文档流**，后面的普通流元素在布局时不会再按照原来的位置考虑这个浮动元素，但**行内内容会避让浮动元素**。

例如：

```text
┌──────────────────────────┐
│ ┌──────┐                 │
│ │ float│  文字文字文字   │
│ │      │  文字文字文字   │
│ └──────┘  文字文字文字   │
│           文字文字文字   │
└──────────────────────────┘
```

## 二、浮动最核心的问题：高度塌陷 {#kaj-h-872e3a90-a429-488a-b231-e85016bb461d}

这是面试最重要的地方。

假设：

```html
<div class="parent">
    <div class="child"></div>
</div>
```

```text
.parent {
    background: pink;
}

.child {
    float: left;
    width: 100px;
    height: 100px;
}
```

由于 `child` 浮动，**脱离普通文档流**。

于是父元素计算自身高度时，不再把这个浮动子元素当作普通流中的内容。

可能出现：

```text
┌───────────────┐
│   parent      │ ← 高度可能变成 0
└───────────────┘

┌──────┐
│child │ ← 浮动元素还在
│      │
└──────┘
```

这就是所谓的：

> **高度塌陷。**

它可能进一步导致后面的元素跑到不该出现的位置。

## 三、怎么解决浮动？ {#kaj-h-6fa1b227-ee85-45d7-b3f9-97f4d75ccb8b}

常见方案可以记 4 种。

### ① 给父元素设置固定高度 {#kaj-h-043132f2-d5ed-410f-a270-24518abccad6}

```text
.parent {
    height: 100px;
}
```

简单粗暴，但缺点是：

> **内容高度变化时不够灵活。**

所以实际开发一般不推荐。

---

### ② 在最后增加一个清除浮动的元素 {#kaj-h-f070d595-ee37-45dc-9542-cea4c4b63a84}

```html
<div class="parent">
    <div class="child"></div>
    <div class="clear"></div>
</div>
```

```text
.clear {
    clear: both;
}
```

`clear` 的真正含义不是：

> “把前面的浮动元素清除掉。”

而是：

> **这个元素不能和前面的浮动元素相邻。**

因此它会被迫移动到浮动元素下面。

```text
浮动元素
┌──────┐
│      │
└──────┘
        ↓
    clear: both
        ↓
┌───────────────┐
│ clear 元素    │
└───────────────┘
```

这样父元素就可以被这个清除元素撑起来。

---

### ③ 父元素创建 BFC {#kaj-h-73d4aaa0-7809-4c42-9ecf-791571976982}

例如：

```text
.parent {
    overflow: hidden;
}
```

为什么可以解决高度塌陷？

因为：

> **BFC 在计算自身高度时，会把浮动子元素也计算进去。**

所以：

```text
parent
┌──────────────────┐
│ ┌──────┐         │
│ │float │         │
│ │      │         │
│ └──────┘         │
└──────────────────┘
       ↑
   高度被撑起来
```

---

### ④ `::after` 清除浮动 {#kaj-h-c9d7906e-de6c-42a7-8f95-234224ae29c8}

现在比较常见的写法：

```text
.clearfix::after {
    content: "";
    display: block;
    clear: both;
}
```

本质上就是：

> **通过伪元素生成一个块级元素，然后让它** `clear: both`**，把它推到浮动元素下面，从而撑起父元素。**
> 
> 
> 
> **clearfix 加在需要“被浮动子元素撑开”的父元素上。**
> 
> 
> 
> ## 四、BFC 到底是什么？ {#kaj-h-b5beae58-6902-40b7-959c-dbd173340f63}
> 
> 
> 
> 你原来的描述有点复杂，面试时可以简单理解成：
> 
> 
> 
> > **BFC（Block Formatting Context）是一块独立的布局区域。**
> 
> 
> 
> 你可以把它想象成：
> 
> 
> 
> ```text
> 外部世界
> ──────────────────────
> 
>         BFC
> ┌─────────────────────┐
> │                     │
> │   BFC内部的元素      │
> │                     │
> │                     │
> └─────────────────────┘
> 
> ──────────────────────
> 外部世界
> ```
> 
> 
> 
> BFC 内部的布局和外部相对独立。
> 
> 
> 
> 因此 BFC 最重要的两个特点你可以记：
> 
> 
> 
> > **① BFC 内部的浮动元素会参与 BFC 高度计算。**  
> >   
> > **② BFC 的区域不会和浮动元素发生重叠。**
> 
> 
> 
> 这两个特点正好对应了 BFC 两个经典应用。
> 
> 
> 
> ## 五、BFC 为什么能解决浮动高度塌陷？ {#kaj-h-fce593d0-5ced-4aa2-bd71-00289f015f5b}
> 
> 
> 
> 例如：
> 
> 
> 
> ```text
> .parent {
>     overflow: hidden;
> }
> ```
> 
> 
> 
> `overflow: hidden` 会让 `parent` 创建 BFC。
> 
> 
> 
> 那么：
> 
> 
> 
> ```text
> 原来：
> 
> parent
> ┌──────────┐
> │          │
> └──────────┘
>    ↑
> 高度塌陷
> 
> float
> ┌──────┐
> │      │
> │      │
> └──────┘
> ```
> 
> 
> 
> 变成：
> 
> 
> 
> ```text
> BFC parent
> ┌──────────────┐
> │ ┌──────┐     │
> │ │float │     │
> │ │      │     │
> │ └──────┘     │
> └──────────────┘
> ```
> 
> 
> 
> 因为：
> 
> 
> 
> > **BFC 在计算高度时会把浮动元素计算进去。**
> 
> 
> 
> 所以父元素被撑开。
> 
> 
> 
> ## 六、BFC 为什么可以实现两栏布局？ {#kaj-h-d4441972-dbcd-4f22-bb30-ad7775f2a7e7}
> 
> 
> 
> 这是另一个非常经典的面试题。
> 
> 
> 
> ```text
> .left {
>     width: 100px;
>     float: left;
> }
> 
> .right {
>     overflow: hidden;
> }
> ```
> 
> 
> 
> 左边：
> 
> 
> 
> ```text
> ┌──────┐
> │ left │
> │      │
> └──────┘
> ```
> 
> 
> 
> 因为 `left` 浮动，普通流中的 `right` 可能会出现在它后面。
> 
> 
> 
> 但 `right` 设置：
> 
> 
> 
> ```text
> overflow: hidden;
> ```
> 
> 
> 
> 创建 BFC。
> 
> 
> 
> 而 BFC 有一个重要特点：
> 
> 
> 
> > **BFC 区域不会和浮动元素发生重叠。**
> 
> 
> 
> 于是：
> 
> 
> 
> ```text
> ┌──────┬─────────────────────┐
> │ left │        right        │
> │      │                     │
> └──────┴─────────────────────┘
>  100px       剩余空间
> ```
> 
> 
> 
> 因此可以实现：
> 
> 
> 
> > **左侧固定宽度 + 右侧自适应。**
> > 
> > 
> > 
> > ## 七、Margin 重叠也可以顺便这样理解 {#kaj-h-61cd143b-c5a9-4d59-b818-b765be7d588d}
> > 
> > 
> > 
> > 两个普通块级元素：
> > 
> > 
> > 
> > ```text
> > .a {
> >     margin-bottom: 30px;
> > }
> > 
> > .b {
> >     margin-top: 20px;
> > }
> > ```
> > 
> > 
> > 
> > 很多人以为间距是：
> > 
> > 
> > 
> > ```text
> > 30 + 20 = 50px
> > ```
> > 
> > 
> > 
> > 实际上可能发生**margin collapse（外边距折叠）**：
> > 
> > 
> > 
> > ```text
> > A
> > ↓
> > 30px
> > ↓
> > 20px
> > ↓
> > B
> > ```
> > 
> > 
> > 
> > 最终间距：
> > 
> > 
> > 
> > ```text
> > max(30, 20) = 30px
> > ```
> > 
> > 
> > 
> > 而不是 50px。
> > 
> > 
> > 
> > ---
> > 
> > 
> > 
> > ## 为什么 BFC 可以解决 margin 重叠？ {#kaj-h-3d71d278-9cf7-46e4-b125-c0fbb930b590}
> > 
> > 
> > 
> > 因为 BFC 是一个**独立的布局环境**。
> > 
> > 
> > 
> > 比如：
> > 
> > 
> > 
> > ```html
> > <div class="parent">
> >     <div class="child"></div>
> > </div>
> > ```
> > 
> > 
> > 
> > 如果父子元素的 margin 发生折叠，可以让父元素创建 BFC：
> > 
> > 
> > 
> > ```text
> > .parent {
> >     overflow: hidden;
> > }
> > ```
> > 
> > 
> > 
> > 这样父子元素就处在不同的格式化上下文中，可以避免这种 margin 折叠。
> > 
> > 
> > 
> > ## 八、最终你可以这样总结“浮动” {#kaj-h-bcbff84e-08b4-4fdd-9967-cae04e9026d7}
> > 
> > 
> > 
> > 面试的时候建议直接用下面这版：
> > 
> > 
> > 
> > > **浮动最初主要用于实现文字环绕，但由于浮动元素会脱离普通文档流，因此在使用浮动布局时容易产生高度塌陷等问题。**
> > > 
> > > 
> > > 
> > > **高度塌陷**是指父元素没有设置高度，子元素浮动后脱离普通文档流，父元素计算高度时无法通过浮动子元素撑开。
> > > 
> > > 
> > > 
> > > 解决浮动常见有几种方式：给父元素设置固定高度、增加 `clear: both` 的清除元素、让父元素创建 BFC，以及使用 `::after` 伪元素清除浮动。其中现在比较常见的是 **clearfix +** `::after` 或直接使用其他现代布局方式，例如 Flex。
> > > 
> > > 
> > > 
> > > `clear` 的作用并不是清除浮动元素本身，而是规定当前元素不能和前面的浮动元素相邻，通常使用 `clear: both`。
> > > 
> > > 
> > > 
> > > **BFC 可以理解为一个独立的块级格式化上下文。** BFC 内部的布局相对独立，并且计算 BFC 高度时会包含浮动元素，因此可以解决高度塌陷；同时 BFC 不会与浮动元素发生重叠，因此还可以实现左侧固定、右侧自适应的两栏布局。另外，BFC 还可以避免部分 margin 折叠问题。
> > 
> > 
> > 
> > ### 最后压缩成一条“知识链” {#kaj-h-3ab177d1-4310-4b1e-bc79-3a808ac1ec43}
> > 
> > 
> > 
> > ```text
> > float
> >   ↓
> > 脱离普通文档流
> >   ↓
> > 父元素可能无法被浮动子元素撑开
> >   ↓
> > 高度塌陷
> >   ↓
> > 解决：
> >   ├─ clear: both
> >   ├─ clearfix::after
> >   ├─ 创建 BFC
> >   └─ 现代开发直接使用 Flex / Grid
> > ```
> > 
> > 
> > 
> > 你现在复习这部分时，**最值得真正搞懂的是** `float → 高度塌陷 → clear → BFC` **这条因果链**，而不是死背 BFC 的所有触发条件。
